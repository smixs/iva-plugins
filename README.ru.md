# iva-plugins

Marketplace [Ивы](https://github.com/smixs/iva) по умолчанию: список плагинов в git-репозитории,
имя и его источник. Не реестр: центра нет, модерации нет, разрешения на публикацию ни у кого
спрашивать не надо. Сам список лежит в `.agents/plugins/marketplace.json` по конвенции Codex,
поэтому его прочитают и другие клиенты (ADR-0009).

## Что в списке

| Плагин           | Что это                                                                                                        |
| ---------------- | -------------------------------------------------------------------------------------------------------------- |
| [trace](./trace) | Вьюер журнала ходов: схема Ивы с подсвеченным путём хода, лента ходов и реплей.                                 |
| [hello](./hello) | Демо для авторов: самый маленький плагин с кодом, один скилл и один тул.                                        |

## Поставить себе

Этот список у Ивы дефолтный, поэтому плагин из него ставится по имени:

```bash
iva plugin add trace
iva plugin list --available    # что предлагают твои маркетплейсы
```

Папка ставится так же. Именно так плагин пробуют, пока его нет ни в одном списке:

```bash
iva plugin add ~/dev/iva-plugins/hello
iva plugin list
```

Свой репозиторий тоже годится в источник: `iva plugin add owner/repo`, и `@ref`, если нужна
ветка или тег. Ива пинует коммит и запоминает его, так что `iva plugin sync` потом восстановит
плагин без тебя.

## Опубликовать свой

Плагин это папка формата Agent Plugins 1.0.0. Обязателен только `plugin.json`:

```
my-plugin/
  plugin.json                  $schema, name, version, description; extensions { "sh.iva": {} }, если есть код
  skills/<имя>/SKILL.md        скилл: frontmatter с name и description; только прямые дети skills/
  mcp.json                     по желанию: MCP-серверы, stdio или streamable-http
  sh.iva/                      по желанию: наш namespace, здесь живут код и сервисы
    package.json               eve.extension { source, dist } и eve в peerDependencies
    tsconfig.json              с extension обязателен: eve эмитит декларации через tsc
    extension/extension.ts     defineExtension()
    extension/tools/<тул>.ts   один файл, один тул
```

Чего требует клиент: `name` строчными буквами, ни одного симлинка в папке, все пути внутри
папки, и сама папка не больше 2000 записей, 50 МБ и 16 уровней. `dist/` не коммить: код плагина собирает eve
той инсталляции, где он работает, на `iva plugin add` и заново на каждом `iva update`.

Как это делается:

1. Скопируй [hello](./hello) и переименуй. Он собирается и здоровается как есть.
2. Проверь локально: `iva plugin add /путь/к/my-plugin`, потом поговори с Ивой.
3. Запушь в свой git-репозиторий, и он уже публикация: любой поставит его через
   `iva plugin add owner/repo`.
4. Чтобы попасть в этот список, открой pull request с одной записью в
   `.agents/plugins/marketplace.json`: `name`, `source` и строка `description`. `source` с папкой
   этого репозитория годится для плагинов, которые живут здесь; свой репозиторий пишется как
   `{ "source": "url", "url": "https://github.com/owner/repo" }`.

## Правила

Плагины этого репозитория написаны на TypeScript, и Node 24 запускает файлы как есть: ни
сборки, ни бандлера, ни зависимостей, пока плагин не объявит их сам. Типы только стираются,
поэтому и код такой, который стирается: без `enum`, без `namespace`, без полей, объявленных
прямо в конструкторе, а относительный импорт называет файл целиком, `./store.ts`. Корневой
`tsconfig.json` нужен редактору и проверке `--noEmit`, соседний `package.json` задаёт формат
модулей и больше ничего; типы рантайма берутся из чекаута Ивы, потому что сам репозиторий
плагинов ничего не ставит:

```bash
IVA_REPO=~/dev/my/assistant
$IVA_REPO/node_modules/.bin/tsgo --noEmit -p tsconfig.json --typeRoots $IVA_REPO/node_modules/@types
```

Страница вьюера в `trace` намеренно лежит одним HTML-файлом (ADR-0010): страницу, которой нужна
сборка, в папке плагина никто не прочитает. Никого другого это не связывает: сервис плагина это
любая команда, а весь договор между ним и Ивой это `service.json` и переменные окружения
(`IVA_SERVICE_PORT`, `IVA_DATA_DIR`, `PLUGIN_ROOT`, `PLUGIN_DATA`).
