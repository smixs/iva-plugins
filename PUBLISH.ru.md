# Как выложить плагин в Marketplace Ивы

Для владельца Ивы и для агента, который на него работает: самой Ивы, Codex, Claude Code. Шаги
идут по порядку, каждый кончается проверкой. Пока проверка не прошла, дальше не идите.

English: [PUBLISH.md](./PUBLISH.md).

## Что попадает в список

Плагин формата [Agent Plugins 1.0.0](https://agent-plugins.org), который ставится командой
`iva plugin add`, лежит в публичном репозитории автора на GitHub и имеет открытую лицензию.
Отдельный скилл оборачивается в плагин: `plugin.json` и `skills/<имя>/SKILL.md`.

Список проверяется. Запись называет один коммит вашего репозитория, и люди ставят именно его;
новая версия приходит новым pull request.

## 1. Соберите и попробуйте

В Иве попросите нужное своими словами: скилл `make-plugin` соберёт папку и установит её.
Руками: скопируйте [hello](./hello) и идите по разделу «Write your own»
[руководства по плагинам](https://github.com/smixs/iva-agent/blob/main/docs/plugins.md).

Проверка: `iva plugin add /путь/к/my-plugin` ставит плагин, и один настоящий запрос к Иве им
пользуется.

## 2. Уберите личное

Удалите ключи, токены, имена, id чатов, адреса почты, домашние пути и значения по умолчанию,
которые указывают на вашу машину. Ключ читается из `.env` или из `data/plugin-data/<имя>/`, и
README называет его по имени.

Проверка: `grep -rnE "/home/|/Users/|@gmail|[0-9]{8,}:[A-Za-z0-9_-]{30,}" .` не находит вашего.

## 3. Напишите README

В корне плагина: что он делает, что ему нужно, как настроить и как удалить. Два раздела Ива
читает сама, когда предлагает установку, поэтому их вид менять нельзя:

```markdown
## Keys

OPENROUTER_API_KEY

## Network

openrouter.ai, api.telegram.org
```

Только имена, без значений; `none`, если пусто. Добавьте файл `LICENSE`.

## 4. Положите в свой репозиторий

```bash
cd my-plugin
git init -b main && git add -A && git commit -m "my-plugin 0.1.0"
gh repo create <вы>/iva-my-plugin --public --source . --push
gh repo edit <вы>/iva-my-plugin --add-topic iva-plugin
```

По теме находят плагины, которых в списке ещё нет:
[github.com/topics/iva-plugin](https://github.com/topics/iva-plugin). Плагин может лежать в
подпапке большого репозитория, тогда запись называет эту подпапку.

Проверка: на машине, которая этой папки не видела, `iva plugin add <вы>/iva-my-plugin` ставит
плагин.

## 5. Напишите запись

Сделайте форк [smixs/iva-plugins](https://github.com/smixs/iva-plugins) и поправьте два файла.

`.agents/plugins/marketplace.json` читает установленная Ива: имя, источник и одна строка
по-английски не длиннее 140 знаков. Имя совпадает с `name` в вашем `plugin.json`. `sha` — полный
коммит, который вы хотите видеть в списке.

```json
{
  "name": "my-plugin",
  "source": {
    "source": "url",
    "url": "https://github.com/<вы>/iva-my-plugin",
    "sha": "<40 знаков>"
  },
  "description": "What it does, in one line."
}
```

Плагин в подпапке: `"source": "git-subdir"` и `"path": "<папка>"` рядом с `url`.

`cards.json` — карточка на странице [iva-agent.com/ru/plugins](https://iva-agent.com/ru/plugins):

```json
"my-plugin": {
  "title": "My Plugin",
  "category": "tools",
  "author": { "name": "Ваше имя", "github": "<вы>" },
  "repository": "https://github.com/<вы>/iva-my-plugin",
  "added": "2026-11-22",
  "summary": { "en": "Two or three sentences for a person.", "ru": "Два-три предложения для человека." },
  "runs": { "en": "What starts on the machine.", "ru": "Что запускается на машине." },
  "keys": ["OPENROUTER_API_KEY"],
  "network": ["openrouter.ai"]
}
```

`category` — один из id в начале `cards.json`; если ни один не подходит, предложите новый в том
же pull request. `runs` простыми словами говорит, что запускает установка: только скиллы, код
внутри процесса агента, сервис, MCP-сервер, скрипт, который просит `sudo`.

Проверка: `node scripts/check.ts` печатает `ok`.

## 6. Откройте pull request

Один плагин — один pull request с заголовком `Plugin: my-plugin`. Шаблон спросит то, что нужно
для проверки.

Нет `gh` и форка: откройте заявку
[Submit a plugin](https://github.com/smixs/iva-plugins/issues/new?template=plugin.yml) с адресом
репозитория, запись напишет сопровождающий.

## Что читает проверка

Код на названном коммите, а не описание:

- что запускается на машине и с какими правами;
- какие ключи он читает и куда ходит в сеть, в сверке с `## Keys` и `## Network`;
- что в репозитории нет личного и секретов;
- что описание говорит о том, что делает код, включая риски;
- что плагин ставится на чистую Иву и переживает `iva update`.

Плагину откажут, если он скрывает, что запускает, отправляет данные владельца туда, чего нет в
README, ставит себя в обход `iva plugin add` или не читается: сжатый код, бинарные файлы,
загрузки, которые запускаются.

Запись в списке значит, что этот коммит кто-то прочитал. Безопасным для любой машины плагин от
этого не становится: перед установкой кода прочитайте раздел «What you risk» в руководстве.

## Обновить и убрать

Новая версия — pull request, который двигает `sha`; проверка читает разницу между двумя
коммитами. Чтобы убрать плагин из списка, откройте pull request или заявку.

## Как считаются установки

`iva plugin add <имя>` из этого списка сообщает сайту iva-agent.com имя плагина и больше ничего:
ни идентификатора установки, ни аккаунта. Сайт показывает сумму на карточке. Строка
`IVA_PLUGIN_STATS=off` в `.env` Ивы это выключает.
